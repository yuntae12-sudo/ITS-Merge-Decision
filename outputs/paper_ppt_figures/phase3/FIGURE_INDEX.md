# Phase 3 Paper/PPT Figure Index

All figures are generated by scripts under `scripts/figures/`, are
deterministic, and read exclusively from real WOMD/Waymax scene data,
real `MergeEnvironment` rollouts, real Frenet-planner/LTV-MPC outputs,
or the committed `outputs/phase3/robustness/audit_168_maneuvers.{csv,json}`
data. No trajectory, geometry, agent, or number in any figure below is
fabricated or hand-drawn. Shared plotting conventions live in
`scripts/figures/_style.py`; shared rollout-capture logic lives in
`scripts/figures/_rollout.py` (wraps the real, frozen
`MergeEnvironment`/`full_split_evaluator.load_maneuver_specs` API,
matching the precedent already established by
`scripts/audit_phase3_robustness.py`).

Environment: `its-merge` conda env
(`/home/autonav/miniconda3/envs/its-merge/bin/python3`). All commands
below assume `PYTHONPATH=.` from the repo root.

## PPT-ready figures

All figures have `_ppt.png` variants (larger fonts/thicker lines,
16:9-legible). For a talk, the recommended sequence is: Figure 1
(annotated) -> Figure 2 -> Figure 3 -> Figure 4 -> Figure 5 -> one of
the MAN_0071/MAN_0107 limitation figures -> Figure 6/7 as backup/detail
slides.

## Figures that must wait for Phase 4/5

None of the above figures depend on Phase 4 (Formal Rule-Based FSM) or
Phase 5 (PPO) work, which have not been started (correctly, per this
task's constraints). Any future "FSM vs PPO" comparison figure,
reward-curve figure, or trained-policy rollout figure must wait until
those phases exist; this figure set intentionally stops at Phase 3's
frozen boundary.

## Limitations / caveats (repository-wide)

- All rollout-based figures use the fixed MERGE-every-step action
  sequence (Stage 3-G/3-H's own convention) as a downstream
  qualitative demonstration -- none of them evaluate decision quality
  of any policy.
- Figure 2's panel display windows use a fixed local half-width
  centered on each real ego position for legibility (the underlying
  scene is highway-like: long in x, very short in y); this is a
  rendering choice only.
- MAN_0041 is in the VALIDATION split, not TRAIN (confirmed via
  `load_maneuver_specs`) -- captions/labels state this explicitly
  rather than assuming TRAIN.
